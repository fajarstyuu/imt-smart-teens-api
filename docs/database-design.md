# Database design and persistence boundaries

**Status: proposed relational design, not applied migrations.** The current Compose database has no business tables. PostgreSQL 17 is the development infrastructure; Rust/SQLx migrations are a later milestone.

## Source and naming

Canonical specifications: `fajarstyuu/imt-smart-teen` at `8df5bafbe8912e37d2e0ba898732bc9f5d9159b7`, `AGENTS.md`, `docs/rules.md`, `docs/backend.md`, `docs/frontend.md`, `docs/delegation.md`, `docs/handoff.md`. See [API inventory](api-inventory.md) for the inspected frontend commit, owner clarifications, contracts and migration map. In this separate backend repository the root is the specification's conceptual `backend/`; future source belongs in `src/` and migrations in `migrations/`, not a second nested backend directory.

Owner changes: admin replaces teacher; school CMS supports add/edit/delete with soft deletion and active-school selection. School names are normalized centrally; school-name snapshots preserve enrollment history. Catalog permission and reporting school grants stay separate.

## Entity relationships and concurrency interfaces

```text
student -> enrollment -> school ID + school-name-at-enrollment snapshot
                     -> published learning-path -> ordered lesson versions -> sections
                     -> per-lesson progress + section visits
                     -> paired snapshot -> pre-test attempt + post-test attempt
                     -> quiz snapshot -> quiz attempt
attempt -> per-question answers -> selected option rows
question version -> immutable options + private answer key
admin -> explicit school grants -> scoped read-only reports
```

API expected_revision maps to assessment_answers.revision for answer autosaves; immutable question versions are distinct. CMS expected_revision instead compares the owning draft/root revision.

Lock order: any workflow needing both enrollment and attempt locks acquires enrollment first, then attempt. Answer-save locks only its owned attempt and never later enrollment; it checks persisted prerequisites, not a client progress flag. School registration/archive serialize on the same school row; registration checks active state and captures its name within the enrollment transaction.

Composite foreign keys require explicit UNIQUE constraints on their complete referenced column tuples. In particular, section visits require `(lesson_version_id,id)` on sections and answer options require `(snapshot_id,id,question_version_id)` on snapshot questions; the definitions below spell them out rather than relying on an implicit unique subset.


Use one database initially, context-prefixed tables in `public`; reporting reads joins but does not mutate other contexts' tables. UUID keys generated by the application; `timestamptz` server timestamps; `date` form dates; enum-like strings constrained with CHECK. Avoid PostgreSQL ENUM migrations until their benefit outweighs changing values. JSONB is appropriate only for versioned content draft payloads, cached idempotency response and safe audit metadata, not core relational ownership/answer lookup.

### Identity ownership

- `identity_schools(id uuid PK, name text NOT NULL, normalized_name text NOT NULL UNIQUE, revision bigint NOT NULL DEFAULT 1 CHECK >0, created_at timestamptz NOT NULL, updated_at timestamptz NOT NULL, archived_at timestamptz NULL)`. Status derives from archived_at (do not store a second status flag). Admin-managed directory only; reject unknown/archived school IDs for new enrollments instead of auto-creating rows from free text. Normalization is NFC + trim/collapse whitespace + casefold, centralized in the identity domain and tested with Unicode examples. Keep normalized names globally unique, including archived records. Add an index `(normalized_name,id) WHERE archived_at IS NULL` for ordered active listings; substring search can initially scan the small directory, no speculative trigram extension. School labels are not authorization proof. Admin school grants remain explicit, never inferred from labels. No automatic cross-device recovery.
- `identity_students(id uuid PK, display_name text NOT NULL, created_at timestamptz)`. Do not deduplicate students on name/date; duplicate humans possible by design without verified recovery.
- `identity_admins(id uuid PK, email text NOT NULL, display_name text, password_hash text, active boolean, can_manage_content boolean, can_manage_schools boolean NOT NULL DEFAULT false, created_at timestamptz)`. Unique index on lower(email); hashes Argon2id only.
- `identity_admin_school_grants(admin_id FK, school_id FK, PRIMARY KEY(admin_id,school_id))`.
- `identity_sessions(id uuid PK, token_hash bytea UNIQUE, role text CHECK student/admin, student_id nullable FK, admin_id nullable FK, enrollment_id nullable FK, csrf_binding_hash bytea, created_at,last_seen_at,idle_expires_at,absolute_expires_at,revoked_at timestamptz)`. CHECK exactly the role-appropriate subject exists; student enrollment required, admin enrollment null. Composite FK `(enrollment_id,student_id)` references enrollment ownership. Token hash fixed 32-byte constraint. Expiry/revocation indexed; never store raw cookie token.

### Learning ownership

- `learning_lessons(id uuid PK, state text CHECK draft/published/archived, revision bigint CHECK >0, draft_payload jsonb, created_at,updated_at)`; draft schema corresponds to documented editor DTO, validated before publishing.
- `learning_lesson_versions(id uuid PK, lesson_id FK RESTRICT, version int CHECK >0, title text, description text, published_at timestamptz, UNIQUE(lesson_id,version))`. Immutable.
- `learning_sections(id uuid PK, lesson_version_id FK RESTRICT, section_key uuid, position int CHECK >0, title text, body text, required boolean, UNIQUE(lesson_version_id,section_key), UNIQUE(lesson_version_id,position), UNIQUE(lesson_version_id,id))`. Exposed section ID is row ID; stable section_key tracks across versions but visits always bind to the pinned version.
- `learning_path_drafts(id uuid PK, revision bigint, lesson_ids uuid[], paired_bank_id uuid FK, quiz_bank_id uuid FK, updated_at)`; one configured path initially; validate member IDs and roles through application policies. Array is editable ordering only, not historical truth.
- `learning_path_versions(id uuid PK, version int UNIQUE, paired_bank_version_id FK RESTRICT, quiz_bank_version_id FK RESTRICT, published_at timestamptz)`.
- `learning_path_items(path_version_id FK RESTRICT, lesson_version_id FK RESTRICT, position int, PRIMARY KEY(path_version_id,lesson_version_id), UNIQUE(path_version_id,position))`.
- `learning_enrollments(id uuid PK, student_id FK RESTRICT, school_id FK RESTRICT, school_name_at_enrollment text NOT NULL, form_date date, path_version_id FK RESTRICT, created_at,completed_at timestamptz, UNIQUE(id,student_id))`. Student identity at enrollment is retained; changes must not rewrite history. Copy the active school name into school_name_at_enrollment during registration so admin rename/archive does not rewrite historical labels. Reporting scope/filtering uses immutable school_id, not this display snapshot.
- `learning_lesson_progress(enrollment_id FK RESTRICT, lesson_version_id FK RESTRICT, opened_at timestamptz, completed_at timestamptz NULL, PRIMARY KEY(enrollment_id,lesson_version_id))`; CHECK completion implies opened and completed_at>=opened_at.
- `learning_section_visits(enrollment_id,lesson_version_id,section_id,first_visited_at, PRIMARY KEY(enrollment_id,section_id))`; composite FK to lesson_progress and section/lesson version ensures a section belongs to that pinned lesson. Membership in enrollment path additionally checked in locked application workflow.

### Assessment ownership

- `assessment_banks(id uuid PK, kind text UNIQUE CHECK paired/quiz, revision bigint, state text)`; exactly two initial banks, not one bank per assessment type.
- `assessment_questions(id uuid PK, bank_id FK RESTRICT, revision bigint, state text, draft_payload jsonb, position int CHECK >0)`.
- `assessment_question_versions(id uuid PK, question_id FK RESTRICT, version int, text text, type text CHECK single/multiple, required boolean, scoring_rule text CHECK exact_set_v1, max_points numeric(12,4) CHECK >0, UNIQUE(question_id,version))`.
- `assessment_options(id uuid PK, question_version_id FK RESTRICT, position int, text text, is_correct boolean, UNIQUE(question_version_id,position), UNIQUE(question_version_id,id))`. Private answer key; explicit student-safe DTO never serializes is_correct.
- `assessment_bank_versions(id uuid PK, bank_id FK RESTRICT, version int, published_at, UNIQUE(bank_id,version))`; `assessment_bank_items(bank_version_id FK,question_version_id FK,position,PRIMARY KEY(bank_version_id,question_version_id),UNIQUE(bank_version_id,position))`.
- `assessment_snapshots(id uuid PK, enrollment_id FK RESTRICT, kind text CHECK paired/quiz, bank_version_id FK RESTRICT, created_at, UNIQUE(enrollment_id,kind), UNIQUE(id,enrollment_id))`.
- `assessment_snapshot_questions(id uuid PK, snapshot_id FK RESTRICT, question_version_id FK RESTRICT, position int, UNIQUE(snapshot_id,question_version_id), UNIQUE(snapshot_id,position), UNIQUE(snapshot_id,id), UNIQUE(snapshot_id,id,question_version_id))`. Immutable references to immutable versions freeze text/options/key/rule; copying mutable CMS JSON is not required. Both pre/post reference the same paired snapshot ID; quiz uses quiz snapshot. No mutable option reordering.
- `assessment_attempts(id uuid PK,enrollment_id FK RESTRICT,snapshot_id uuid,assessment_type text CHECK pre_test/quiz/post_test,attempt_number int CHECK >0,status text CHECK in_progress/submitted,created_at,submitted_at,earned_points numeric(12,4) NULL,max_points numeric(12,4) NULL,score_percent numeric(5,2) NULL,UNIQUE(enrollment_id,assessment_type,attempt_number),UNIQUE(id,snapshot_id))`. Composite FK `(snapshot_id,enrollment_id)` enforces same enrollment; type↔snapshot kind checked by application. Partial UNIQUE `(enrollment_id,assessment_type) WHERE status='in_progress'`; initial application permits attempt_number=1 only. CHECK submitted fields consistent, scores 0–100.
- `assessment_answers(attempt_id uuid,snapshot_id uuid,snapshot_question_id uuid,revision bigint CHECK >0,saved_at timestamptz,earned_points numeric(12,4) NULL,is_correct boolean NULL,PRIMARY KEY(attempt_id,snapshot_question_id),UNIQUE(attempt_id,snapshot_question_id,snapshot_id))`. Composite FKs `(attempt_id,snapshot_id)` and `(snapshot_id,snapshot_question_id)` forbid cross-snapshot answers. Row existence with zero selections means cleared/unanswered, not wrong.
- `assessment_answer_options(attempt_id,snapshot_question_id,snapshot_id,question_version_id,option_id,PRIMARY KEY(attempt_id,snapshot_question_id,option_id))`. FK to owning answer; FK `(question_version_id,option_id)` to assessment_options; composite FK from `(snapshot_id,snapshot_question_id,question_version_id)` to a UNIQUE triple on assessment_snapshot_questions. These composite constraints prevent a valid option from another question being persisted. In application validate cardinality and option set before write.

### Anthropometry and platform ownership

- `anthropometry_measurements(id uuid PK,enrollment_id FK RESTRICT,weight_kg numeric(12,4),height_cm numeric(12,4),bmi numeric(38,12),calculation_rule_version text CHECK bmi_v1,created_at timestamptz)`. CHECK numeric values finite and >0 (explicitly reject PostgreSQL numeric NaN/Infinity); validate max representability before conversion. API rejects inputs needing >4 decimal places rather than silently rounding; serialize numbers, not strings, using checked conversion. BMI stored at 12 decimals; display rounding half-up to one decimal, never calculate from display value. Widths are representation limits, not medically validated healthy ranges. Future precision changes require a new policy/version and tests.
- `platform_idempotency(scope_hash bytea,operation text,key text,payload_hash bytea,status_code int,response_body jsonb,created_at,expires_at,PRIMARY KEY(scope_hash,operation,key))`. Key length 1–128 ASCII; scope may be verified principal or pre-login CSRF context. No secrets in response cache; cookies regenerated/reissued safely from session identity, never store a raw session token in cached JSON. Enrollment replay must be able to reissue a new session for the same CSRF-bound operation without creating another enrollment; do not promise replay of the exact cookie token.
- `platform_audit_events(id uuid PK,actor_session_id uuid NULL,actor_admin_id uuid NULL,action text,resource_type text,resource_id uuid,resource_version text NULL,request_id text,created_at timestamptz,safe_metadata jsonb)`. No answer payloads, password/token, or duplicated personal details. Auth attempts without session can use a redacted actor key; retention policy required before production.

### Query-driven indexes

- Enrollments `(student_id,created_at DESC,id DESC)`, `(school_id,form_date,id)`, `(school_id,created_at DESC,id DESC)`.
- Attempts `(enrollment_id,assessment_type,status)`, `(assessment_type,submitted_at DESC,id DESC)` plus active unique index above.
- Answers PK supplies attempt/question reads; add `(snapshot_question_id,attempt_id)` and snapshot question `(question_version_id,snapshot_id)` for cross-student reports.
- Progress PK supplies enrollment lookup; section visit PK prevents duplicate events.
- Measurements `(enrollment_id,created_at DESC,id DESC)`.
- Sessions token_hash unique, `(idle_expires_at)` and `(absolute_expires_at)` for bounded cleanup; admin grant composite PK for scoped joins.
- Idempotency `(expires_at)`; audit `(created_at,id)` and `(resource_type,resource_id,created_at)`.
- Validate report plans with `EXPLAIN (ANALYZE,BUFFERS)` on synthetic scaled data in a later schema milestone. Do not add speculative indexes to every column.

### Transaction / concurrency matrix

- School mutations: lock school row, check expected revision, update name or archive with audit event in the same transaction. Registration locks the selected school row before enrollment creation; publication-dependent workflows follow a consistent lock order. No cascade deletion; only active-school selection is removed by archive.
- Enrollment: lock/validate selected active school, capture school_name_at_enrollment, verify published manifest, create student/enrollment, paired+quiz immutable snapshot references, pre attempt and session, idempotency record in one transaction; no partial login state.
- Answer save: lock own attempt `FOR UPDATE`, validate open/ownership/snapshot, compare answer revision (absent=0), replace option rows, increment revision and commit. All autosaves lock attempt before answer; same lock order as submission avoids races/deadlocks.
- Submission: lock enrollment then attempt; save pipeline must never acquire enrollment after holding attempt. Check current prerequisites/answers, calculate server score, save per-answer/total result and submission, update enrollment completion if post, audit/idempotency, commit. An autosave either commits before scoring or sees submitted and fails. Locks must be acquired in a single globally documented order; lesson completion and measurement also lock enrollment first.
- Lesson visit/completion: enrollment lock → validate pinned path/prerequisites → idempotent progress/visit rows. No timer or comprehension claim.
- Measurement: enrollment lock → validate quiz complete/post not submitted → calculate/insert, audit/idempotency; post unlock derived from committed measurement existence.
- Publication: lock draft/root revision; create immutable versions/manifest; never update referenced published rows. Historical FK deletion uses RESTRICT.
- Reports: authorized read-only SQL projections from attempt snapshots, not latest CMS text; school grant filter in SQL, not after pagination.
- Retry bounded recognized serialization/deadlock failures only; never retry an arbitrary mutation without transactional idempotency.
